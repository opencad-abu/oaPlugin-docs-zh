oaPlugin / aividmfilesys

aividmfilesys

这是 OA DM 文件系统插件，负责库、cell、view、file 的路径映射、锁、访问控制和 cache/temporary 文件处理。它和 aividmfilesysbase 一起构成 DM FileSys 侧实现。

产物：liboaAiviDMFileSys.so
接口：ILib、IDMAccess、ILocking、IAccessControl、IDMSystemCaps、IPlugInAbort
职责：把 OA 对象映射到实际文件系统，并在写入前后维护锁状态。

导出入口

符号用途
oaAiviDMFileSysInit()注册工厂别名并初始化插件入口。
oaDMFileSysInit()兼容别名，等同于 oaAiviDMFileSysInit()。
oaAiviDMFileSysExit()退出清理，释放锁相关残留。
FileSysExit()兼容退出入口。
getClassObject()OA 加载器标准入口，返回工厂对象。

主类和接口

组件说明
oaDMFileSysComp主实现类，承担 init、对象创建、路径映射、锁和权限控制。
Locking文件锁实现，处理单文件、递归对象和编辑锁文件。
FileLocking进程级锁状态单例，负责恢复、清理和 daemon 交互。

常用方法

方法作用
init()接收 libName、libPath、writePath 和 DM 属性。
getPath()把 DM 对象转换成磁盘路径。
fileGetCache() / fileReleaseCache()管理缓存文件路径。
getAccess() / releaseAccess()控制库级别访问权限。
lock() / unlock()对 DM 文件加锁和解锁。
getLockStatus()返回当前文件锁状态。
queryCapability() / getMetric()提供 DM 系统能力和度量查询。

调用流程

  1. OA 打开库时创建 oaDMFileSysComp，由 init() 读取路径和属性。
  2. 对 cell 或 view 进行操作时，插件根据对象名拼出物理文件路径。
  3. 写入前调用 lock() / getAccess()，读写权限和锁状态在这里统一控制。
  4. 退出或恢复时由 FileLocking 做清理，避免残留锁文件。

这个模块解决的是“文件系统如何被 OA 理解”，而不是版本控制。版本内容可以继续交给 aivivc 或后续状态模块处理。
