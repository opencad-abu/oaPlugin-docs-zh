oaPlugin / aivivc 使用说明

aivivc

oaPlugin 是 AIVI 项目的一部分。aivivc（AIVI Version Control）是其中的一个模块，用作基于 Git/SVN 的 OA 数据简单版本管控，并提供 OpenAccess、Virtuoso Library Manager 和 Cadence GDM 的桥接入口。

定位：OA 版本管控桥梁，优先服务 AIVI，并兼容 Virtuoso 平台。
边界：Git/SVN 负责版本内容；编辑权限和协同锁后续可以交由独立状态模块实现。
入口：命令行 aivivc-gdm、GDM native wrapper、Library Manager SKILL 菜单。

职责边界

OA 插件入口

通过 liboaAiviVC.so 注册 OA VC system，实现 IVersionControl、IVCSystem 和相关插件入口。

GDM 命令适配

aivivc-gdm 解析 GDM 风格参数，执行 status、co、ci、cancel、update、history。

Virtuoso 菜单桥

SKILL 代码把 Library Manager 选择对象解析为 OA 文件路径，并调用 GDM 适配器完成动作。

快速开始

  1. 设置 OAPLG_ROOT、OACPP_ROOT 和目标 WORKAREA。
  2. 执行统一构建，确认 RHEL90 构建产物生成。
  3. 启动 Virtuoso 前 source 环境脚本，保证进程继承 PATH、LD_LIBRARY_PATH、OA_PLUGIN_PATH 和 GDM 变量。
  4. 在 Library Manager 选择 library/cell/view，使用 Status...、Make Editable、Commit... 或 Cancel Edit...。
export OAPLG_ROOT=...
export OACPP=...
export WORKAREA=...

cd "$OAPLG_ROOT"
./build_all.sh opt

source "$OAPLG_ROOT/scripts/aivivc_virtuoso_env.sh" "$WORKAREA"
aivivc-gdm status -cdslib "$WORKAREA/cds.lib" -lib myLib.myCell:schematic/sch.oa

状态模型

git status clean 只代表内容没有改动，不代表 GDM 已 check-in。当前实现会把 checkout 标记和文件权限结合起来，让未 checkout 的 OA 数据默认只读，Make Editable 后才恢复可写。

用户状态GDM 状态文件权限说明
已受控，未 checkoutgdmStateCIREAD默认只读，直接编辑应被阻止。
当前用户 Make EditablegdmStateCOWRITE写入 checkout 标记，允许编辑 OA 数据。
其它用户 checkoutgdmStateCOEREAD报告为 Locked，当前用户不能直接打开写权限。
远端有更新OUT_OF_DATEREAD需要先执行 Update，再继续编辑。

Library Manager 用户 flow

  1. 选中受控 OA 对象，执行 Status... 查看当前状态。
  2. 需要编辑时先执行 Make Editable。该动作会写 checkout marker，并把受控文件设为当前用户可写。
  3. 编辑并保存 OA 数据后执行 Commit...。即使 Git/SVN 没有内容改动，aivivc 也会释放 checkout marker 并恢复只读。
  4. 不保留编辑时执行 Cancel Edit...，回退内容并释放 checkout marker。
  5. 远端或 SVN 服务端有更新时先执行 Update，再继续编辑。

接口对接

接口层对接方式
命令行通过 aivivc-gdm 提供 status、co、ci、cancel、update、history 等动作。
GDM通过 libgdmaivivc_sh.so 导出 GDM wrapper 函数表，并把请求转发给 aivivc-gdm。
SKILLLibrary Manager 菜单 callback 解析选中对象路径，再调用 GDM adapter。
OA 插件通过 oaAiviVC.plg 和 aivivc.plg 让 OA 发现 AIVI VC system。
详细接口说明见 API 文档，完整 Virtuoso 接入步骤见 Virtuoso 集成 flow。
