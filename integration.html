oaPlugin / Virtuoso 集成

AIVIVC Virtuoso 集成指导

本页描述 aivivc 在 Virtuoso 中的加载和测试方式。aivivc 提供 OA VC 插件和 Cadence 原生 GDM 封装库两条路径，Library Manager 菜单作为用户交互桥。

目标

  1. OA VC 插件：liboaAiviVC.so 通过 OA 插件管理器加载，实现 IVersionControl。
  2. Cadence 原生 GDM 封装库：libgdmaivivc_sh.so 导出 gdmaivivcWrapFuncs，薄封装调用 aivivc-gdm。
  3. Library Manager 菜单：aivivcLibMgr.il 创建菜单，aivivcCallbacks.il 执行动作回调。

端到端集成 flow

  1. 构建 oaPlugin，确认 liboaAiviVC.so、libgdmaivivc_sh.so、aivivc-gdm、aivivcgdmconfig 都已生成。
  2. 在工作区根目录准备 Git/SVN 工作副本和 cds.lib，library 路径必须落在同一个工作副本内。
  3. 启动 Virtuoso 前执行 source 加载环境脚本。
  4. .cdsinit 只加载 aivivcCallbacks.il。
  5. Library Manager customization context 加载 cdsLibMgr.il，由它创建菜单并在 LM 上下文内加载回调。
  6. 工作区或 library 的 cdsinfo.tag 写入 DMTYPE aivivc。
  7. 先用 shell 验证适配器，再在 CIW 用 gdmCreateSpec/gdmstatus 验证原生封装库。
  8. 最后在 Library Manager 中执行 Status...、Make Editable、Commit...、Cancel Edit...。

构建

export OAPLG_ROOT=...
export OACPP=...
export SYSNAME=linux_rhel90_64
export OPTMODE=opt

cd "$OAPLG_ROOT"
./build_all.sh opt

ls -l "$OAPLG_ROOT/lib/$SYSNAME/$OPTMODE/liboaAiviVC.so"
ls -l "$OAPLG_ROOT/lib/$SYSNAME/$OPTMODE/libgdmaivivc_sh.so"
nm -D --defined-only "$OAPLG_ROOT/lib/$SYSNAME/$OPTMODE/libgdmaivivc_sh.so" | grep gdmaivivcWrapFuncs

启动 Virtuoso 前的环境

推荐从同一个 shell 启动 Virtuoso，确保进程继承插件路径、GDM 变量和 Git/SVN 命令路径。

export OAPLG_ROOT=...
export OACPP=...
export WORKAREA=...
export SYSNAME=linux_rhel90_64
export OPTMODE=opt

source "$OAPLG_ROOT/scripts/aivivc_virtuoso_env.sh" "$WORKAREA"

环境脚本会设置或补齐：

变量用途
PATH包含构建产物目录和 aivivc-gdm/aivivcgdmconfig。
LD_LIBRARY_PATH包含 oaPlugin、oacpp、Python/SVN 运行库。
OA_PLUGIN_PATH让 OA 插件管理器找到 oaAiviVC.plg 和 aivivc.plg。
GDM_USE_SHLIB_ENVVAR / CDS_GDM_SHLIB_LOCATION让 Cadence GDM 从指定目录加载 libgdmaivivc_sh.so。
AIVIVC_ROOT / AIVIVC_GDM_ADAPTER / AIVIVC_SKILL_DIR给 OA 插件、GDM 封装库和 SKILL 菜单使用。

脚本默认会安装/刷新 Library Manager 资源、补写工作区 DMTYPE aivivc，并执行 aivivc-gdm protect 把未 checkout 的受控文件恢复为只读。

export AIVIVC_INSTALL_LIBMGR_ASSETS=0
export AIVIVC_PROTECT_ON_STARTUP=0
export AIVIVC_INSTALL_WORKAREA_TAG=0
export AIVIVC_SET_CDS_WORKAREA=0

OA VC 插件加载

OA 插件管理器通过 OA_PLUGIN_PATH 找到 data/plugins/oaAiviVC.plg 和 data/plugins/aivivc.plg，运行时加载 liboaAiviVC.so。

export AIVIVC_ROOT="$WORKAREA"
export AIVIVC_BACKEND=auto

Library Manager 菜单

SKILL 代码分成两个上下文：

文件加载位置职责
aivivcCallbacks.ilCIW 或 LM 上下文动作和回调函数、路径解析、菜单 pre-map callback。
aivivcLibMgr.il / cdsLibMgr.ilLibrary Manager customization context创建菜单，并在 LM 上下文内加载回调。
 
; .cdsinit
load(strcat(getShellEnvVar("AIVIVC_SKILL_DIR") "/aivivcCallbacks.il"))

; Library Manager customization context
load(strcat(getShellEnvVar("AIVIVC_SKILL_DIR") "/cdsLibMgr.il"))
菜单项Adapter 命令状态/权限效果
Status...aivivc-gdm status -file "$TARGET"弹窗显示 Check in、Check out、Out of date、Locked 等状态。
Make Editableaivivc-gdm co -file "$TARGET"写 checkout marker，并把受控文件置为当前用户可写。
Commit...aivivc-gdm ci -message "$MSG" -file "$TARGET"提交内容；无内容改动也会释放 checkout marker。
Cancel Edit...aivivc-gdm cancel -file "$TARGET"revert/clean 后释放 marker，并恢复只读。
Updateaivivc-gdm update -file "$TARGET"拉取/更新版本，成功后保护未 checkout 的文件。
History...aivivc-gdm history -file "$TARGET"显示最近历史。

GDM 原生封装库集成

Cadence GDM 加载器会按 DMTYPE 拼接查找 gdm%sWrapFuncs。AIVIVC 的 DMTYPE 是 aivivc，对应符号为 gdmaivivcWrapFuncs，封装库名为 libgdmaivivc_sh.so。

export GDM_USE_SHLIB_ENVVAR=yes
export CDS_GDM_SHLIB_LOCATION="$OAPLG_ROOT/lib/$SYSNAME/$OPTMODE"
export PATH="$OAPLG_ROOT/lib/$SYSNAME/$OPTMODE:$OAPLG_ROOT/src/aivivc/gdm:$PATH"
export LD_LIBRARY_PATH="$OAPLG_ROOT/lib/$SYSNAME/$OPTMODE:${LD_LIBRARY_PATH:-}"

库目录或现场 DM 配置中需要声明：

DMTYPE aivivc

CIW/GDM API 验证

在 CIW 中先确认 Virtuoso 进程继承了启动 shell 的环境：

getShellEnvVar("PATH")
getShellEnvVar("LD_LIBRARY_PATH")
getShellEnvVar("OA_PLUGIN_PATH")
getShellEnvVar("GDM_USE_SHLIB_ENVVAR")
getShellEnvVar("CDS_GDM_SHLIB_LOCATION")
getShellEnvVar("AIVIVC_GDM_ADAPTER")

然后创建 GDM spec 并查询状态：

gdmSpec = gdmCreateSpec("myLib" "myCell" "schematic" "sch.oa" "CDBA")
gdmstatus(gdmSpec 6)
gdmstatus(gdmSpec 7)
场景gdmstatus(... 6)gdmstatus(... 7)
已受控、未 checkoutgdmStateCIgdmStateRead
当前用户 Make Editable/co 后gdmStateCOgdmStateWrite
其它用户 checkoutgdmStateCOEgdmStateRead
未受控或 DMTYPE/GDM 未关联gdmStateNone 或 gdmStateUnmanageablegdmStateNone 或 gdmStateRead

Git/SVN 工作区测试

cd "$WORKAREA"
git status -sb
git config user.name "AIVIVC Test"
git config user.email "aivivc@example.invalid"

aivivc-gdm protect -file "$WORKAREA/myLib"
aivivc-gdm status -cdslib "$WORKAREA/cds.lib" -lib myLib.myCell:schematic/sch.oa
aivivc-gdm status-code -cdslib "$WORKAREA/cds.lib" -lib myLib.myCell:schematic/sch.oa
aivivc-gdm co -cdslib "$WORKAREA/cds.lib" -lib myLib.myCell:schematic/sch.oa
aivivc-gdm ci -message "AIVIVC smoke check" -cdslib "$WORKAREA/cds.lib" -lib myLib.myCell:schematic/sch.oa

SVN 工作区需要先确保 svn 可执行文件和运行库在启动 shell 环境中可见。

故障排查

现象检查点
oaAiviVC load failed检查 OA_PLUGIN_PATH、LD_LIBRARY_PATH 和 liboaAiviVC.so。
no Git/SVN work area found确认目标 library 在 Git/SVN 工作副本内，或显式设置 AIVIVC_ROOT 与 AIVIVC_BACKEND。
gdmaivivcWrapFuncs 找不到检查 CDS_GDM_SHLIB_LOCATION、DMTYPE aivivc，并用 nm 确认符号。
找不到 aivivcgdmconfig检查 PATH 是否包含构建产物目录或 src/aivivc/gdm。
GDM 封装库能加载但操作失败检查 AIVIVC_GDM_ADAPTER、Python/SVN 运行库，并直接运行 aivivc-gdm status -file "$TARGET"。
Library Manager 菜单没有出现确认 .cdsinit 只加载 callbacks，菜单文件由 Library Manager customization context 加载。
